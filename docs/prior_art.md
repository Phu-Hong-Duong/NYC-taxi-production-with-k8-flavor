# Prior art — surveyed, verdicted, revisited (M1 story; M8 revisit for Feast)

Anchor (existence verified 2026-08-12; CONTENTS surveyed live at M1, never from
memory): DataTalksClub's MLOps Zoomcamp — the canonical public MLOps course, built
on this same dataset and target (NYC taxi trip duration) — plus 2–3 strong capstone
repos from its cohorts and any public Feast-on-taxi implementations found live.

Survey protocol: for each practice observed, one row, one verdict, one reason.
Verdicts: ADOPT (they do it better — take it, credit it) · DIFFER (we chose
otherwise — say why, honestly) · SURPASS (we do something none of them do — prove
it, don't assert it). Minimum 6 rows to close M1's story. M8 adds the
feature-store-specific comparison after ours exists.

## Survey method and its honest limits (M1-S3, 2026-08-16)

**All eight sources below were fetched and read on 2026-08-16**, not recalled.
`WebSearch`/`WebFetch` are outside this session's permission allowlist (F-001), so
the survey ran through the two tools that are on it: `curl` against
`raw.githubusercontent.com` for document contents, and the authenticated GitHub
API (`gh api search/repositories`, `gh api repos/<owner>/<name>`) for discovery
and metadata. Star counts and `pushed_at` below are live API readings.

**Three limits, stated rather than glossed:**

1. **"Strong capstone" here means operationally specific, not popular.** The
   surveyed capstones carry 0–3 stars. That is what the population looks like:
   a GitHub search for this exact problem returns mostly course forks and
   homework, and the *substantive* work sits in low-star personal repos. Ranking
   by stars would have surfaced awesome-lists, not practice.
2. **READMEs, not full code audits.** Each verdict cites what the repository
   *documents*. Where a claim is architectural (install order, alert rules,
   feature timestamps) the README is authoritative; where it is about quality,
   this survey does not claim to have verified the implementation.
3. **Sample of six projects + one course.** A SURPASS row below means "none of
   these six do it", not "nobody does it". Rows 11–13 say so in their reasons.

## M8 revisit (Feast) — the row to come back to

Row 4 is the one M8 must argue against its own implementation. The specific
questions F answers that ours must also answer: what timestamp convention makes
leakage structurally impossible; whether the online path reads the *same named
feature service* training used; and where the registry lives relative to the
cluster's destroy blast radius (F puts it in MinIO — ours would face the same
PVC-dies-with-the-cluster problem that sent our DVC remote outside the cluster
at M1-S2).
