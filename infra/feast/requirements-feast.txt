# THE QUARANTINE — Feast's complete transitive set, pinned exactly (M8-S2).
#
# THIS FILE IS NEVER INSTALLED INTO THE PROJECT ENVIRONMENT. It builds
# `.venv-feast/`, an isolated interpreter that this repository's own code never
# imports and that never appears in `uv.lock`.
#
# Why (M8 law 4, measured live at the milestone's draft and re-measured here):
# feast 0.66.0 declares `pandas<3,>=1.4.3`; this project runs pandas 3.0.5. That
# is a hard major-version wall, the full-`mlflow` shape of gotcha #36 — an
# `uv add feast` cannot resolve without dragging the project's numeric core two
# years backwards, and every number this program has published was measured on
# the core it has. So the wall is the design, not the fallback: Feast lives on
# its own side and the two sides exchange PARQUET (M8-S3 measures that seam,
# which is the mlserver precedent — a boundary is only trustworthy once it has
# been measured across).
#
# M8-S4 added exactly two lines — `redis` and `hiredis`, feast's `redis` extra
# (`redis<8,>=4.2.2`, `hiredis<4,>=2.0.0`, read off feast's own metadata). The
# ONLINE store is an in-cluster Redis (ADR-012) and Feast's redis driver refuses
# to import without them: `FeastExtrasDependencyImportError: No module named
# 'redis'`, raised at config load, i.e. before any connection is attempted. They
# are pinned here rather than resolved at install time for this file's whole
# reason — a resolver consulted later can legally answer differently from the one
# that was reviewed. Nothing else moved: `git diff` over this file is +2/-0.
#
# Regenerate:  make feast-quarantine        (builds .venv-feast from this file)
# Re-resolve:  bash scripts/feast_quarantine.sh --resolve   (rewrites this file)
#
# The exit invariant every M8 story asserts: `uv.lock` byte-identical, and no
# distribution named below present in the project graph.
